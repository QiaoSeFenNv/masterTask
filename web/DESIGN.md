# Web 体验预览设计规格

目的：通过可分享链接让其他人体验选包、撕包、选卡和 PAG 揭晓，并查看任务、日历与图鉴。每位访问者的体验数据只保存在自己的浏览器。

视觉方向：沿用现有小游戏的夜色背景、纸质卡包、角色卡面与金色文字。外层为简洁的操作界面，围绕实际游戏画面安排控件。

配色：外层背景 #071119，边框 #29424D，主要文字 #E9DBC1，次要文字 #AFC0C7，焦点 #A8E6CF。卡包与角色沿用现有资产和配色。

字体：外层标题使用 STSong / SimSun / serif；操作说明使用 Microsoft YaHei / sans-serif。Canvas 文字保留现有绘制方式。

布局：电脑上居中放置约 390 像素宽的竖屏体验区，高度随可用窗口调整；手机上游戏区占满可用宽度与高度。顶部提供名称与重新体验按钮，底部显示当前操作提示。输入弹层采用文字标签与可见确认、取消按钮。

交互：鼠标与触摸统一映射到 Canvas 内的坐标。选包增加约半秒的放大移动过渡；撕包跟随拖动，转盘继续跟手，揭晓复用同一 PAG 模板。切后台、窗口调整和再次体验保持可用。

验收：从首页使用真实点击和拖动完成一轮抽卡；看到选包过渡、撕口变化、三张翻面与 PAG 揭晓；任务勾选和手记可保存，刷新可恢复，日历和图鉴可访问；在手机尺寸上操作可用；分享链接加载资源成功，不依赖本地后端或微信登录。

## 图鉴卡面

图鉴使用双列 2:3 竖卡，图片居中 cover 裁切，底部暗色遮罩承载角色名和收藏次数；详情使用同一画面的竖图缩略图。未解锁角色仍隐藏图片和名字。

当前只有侦探专属油画（`game/assets/role-detective.jpg`）；其余角色暂借已有油画场景作底图，不表示它们拥有专属画像，也不影响抽卡概率。后续角色图压缩为 `role-<id>.jpg` 并登记到 `game/js/assets.js` 的 `FILES`，Web 构建会同步复制。

专属角色图只在已解锁卡片进入视口时加载。未加载或解码失败时先用场景底图；全部图片不可用时回退完整渐变卡面。图鉴回归测试：`node --test tools/collection.test.cjs`。
浏览器专项验证：`node tools/collection-web-check.cjs`，覆盖未解锁点击、油画卡面与详情、滚动、页面提示和 320 宽图片失败回退；截图输出到 `tools/.web-preview/collection-*.png`。

## 今日页刮开内容

候选正面仅保留角色名、tagline 与外观；完整介绍不在候选详情中显示。落定揭晓后，今日页的任务背卡由无文字油画覆盖，用户用鼠标或触摸连续擦除，覆盖达到 60% 后转为正常介绍与任务列表。提示放在卡外，滚轮和卡外拖动只滚动。

本机以日期、角色和服务端抽卡 seed 隔离刮开进度；松手、取消、切页、后台和完成时保存。刷新可续刮，重抽/新一天不继承旧进度；已有勾选或手记的历史记录不重新遮盖。专属图未就绪时复用已登记场景，无图使用渐变；无离屏 Canvas 或合成失败时以网格剪裁保持遮盖。

专项验证：`node --test tools/scratch.test.cjs` 与 `node tools/scratch-web-check.cjs`。截图在 `tools/.web-preview/scratch-{covered,partial,revealed,fallback-partial,mobile-revealed}.png`。
